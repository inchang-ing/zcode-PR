你接管一个已在运行的开源贡献流水线。工作文件夹里有一个状态手册,你的第一件事是找到并通读它。

## 启动步骤

1. **定位状态文件夹**:在可访问的磁盘里查找包含 `STATE.md` 与 `rounds-log.md` 的文件夹(常见位置:粘贴本提示词时的工作目录、`E:\zcode-PR\`、或用户指定的路径)。向用户确认路径后再继续。
2. **通读 `STATE.md`** —— 它是你的规则手册(v2):身份与基础设施、十条硬性规则、策略经验(含"系列补全"制胜打法)、在飞 PR 台账、25+ 侦察项目池。所有硬性规则必须严格遵守,尤其:
   - 撞车查证 v3 四查(编号/标题关键词/issue 时间线交叉引用/同文件改动 PR)之后才能认领任何 issue
   - AI 政策筛查:要求披露的仓库如实披露(工具名以当前实际使用的工具为准);禁止 AI 代写 PR 描述的仓库跳过留给用户;绝不写虚假声明
   - 覆盖率门禁:推送修复 PR 前,本地对改动文件跑覆盖率,每个新增分支都要有用例
   - 删除安全:删除/覆盖仅限流水线自己创建的文件,先预览
   - 分支卫生:永远从 origin/main 切新分支,推送前自查提交列表
3. **第一优先级——跟进在飞 PR**(STATE.md 第四节台账,已知在飞:pylint #11474 等 Pierre 复审、mypy #22056 与 #22058 等首评;celery #10714 与 SeaTunnel #12488 已合并):逐个检查 CI 与评审,有评审意见当轮修复推送,基础设施抖动用空提交重触发一次,状态变化更新 STATE.md 并在 rounds-log.md 用 `date -u` 记录。
4. **侦察与执行**:扫描 STATE.md 第五节的 25+ 项目池(48h 窗口、无 assignee、评论 ≤2)+ 系列补全搜索,候选做撞车 v3 四查与时间盒诊断,命中则走完整流程(fork → 环境验证 → 修复+测试+覆盖率自检 → PR)。若 STATE.md 注明名额已满则只侦察与跟进,不新提。
5. **收尾**:在 rounds-log.md 追加本轮摘要(时间戳用 date -u),向用户输出一句话摘要。
