## 本机 git 环境灾难(重要,已踩坑)

1. **`.git/refs` 与 `.git/logs` 会被反复删除** → git 报 "not a git repository"。修复:从 `.git/logs/refs/**` 的 reflog 末行第 2 字段恢复分支 SHA;reflog 也丢了就从 `.git/objects/<SHA前2位>/` 目录拼出完整 SHA(`git cat-file -t` 确认是 commit)。
2. **顶层 tree 对象会丢失** → push 报 "bad tree object"。索引的 tree 缓存会掩盖缺失(`write-tree` 直接返回旧 SHA 不报错)—— 必须 `git read-tree --empty` 先清缓存才会真正重写。
3. **`gh` CLI 不在 PATH**:`C:\Program Files\GitHub CLI\gh.exe` 存在但 PATH 没有 → `gh auth token` 返回空 → push 报 "Invalid username or token"。取 token 必须全路径调用。
4. **GitHub MCP 集成无写权限**:建分支/写文件/开 PR 均 403 "Resource not accessible by integration"。但 gh(全路径)本地有 token(40 位经典 PAT),可写。
5. **代理 `127.0.0.1:57291` 对 github.com 的 CONNECT 时而 502** → push 要带重试循环(20 次 × 8s)。
6. **推送前绝不 `git add -A`**:本机工作区有 CRLF/符号链接差异,`add -A` 会把 16 个无关文件卷进提交(污染 PR)。正确做法:`git read-tree <上游clean SHA>` 设索引 → `git checkout <SHA> -- <目标文件>` 落工作区 → 只 `git add` 目标文件 → `git commit-tree <tree> -p <上游base> -F <msg>` → `git update-ref` → `git push --force`。最后用 `git show --stat` 或 MCP `get_commit` 复核 diff 行数。
7. **覆盖率采集坑**:`pytest --cov=pylint/extensions/private_import`(路径形式)采集不到 → 必须用模块形式 `--cov=pylint.extensions.private_import`;功能测试在 pytest 进程内测不到检查器代码,须用 `coverage run -m pylint ...` 单独跑一次才拿真实覆盖。
