## 补: push_via_api.py 的尾部换行 bug(已修)
- 症状: litellm#46262 CI 的 "Check ruff format" 报 `Would reformat: litellm/.../streaming_handler.py`, 本地 ruff 0.15.3(与 uv.lock 同版本)却说 already formatted。
- 根因: `push_via_api.py` 用 `git show <sha>:<path>` 取内容后走了 `git()` 的 `.stdout.strip()` → **把文件末尾换行吃掉了**, 推上去的 blob 无结尾空行(远端 2565 个 LF vs 本地 2566 行)。判据: 拉远端 blob 到本地跑 `ruff format --diff` 立刻显示 `\ No newline at end of file`。
- 修法: 新增 `git_raw()`(不 strip)专门用于文件内容; 两个分支(litellm `7400ea18`、nbconvert `bff0a5dc`)已重推。
- 教训: 经 API 建 blob 时**文件内容必须逐字节保留**(含结尾换行与编码), 只有 commit message / sha / 作者这类字段才 strip。
